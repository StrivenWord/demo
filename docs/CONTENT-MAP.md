# Content Map

Every visible string on this site falls into one of eight categories below, each with
a different home and a different way to change it. Before editing any text, find its
category here first; several categories look like normal template copy but are
actually generated, and hand-editing them gets silently overwritten.

**Quick reference**

| Category | Where it lives | Hand-edit? | After editing |
|---|---|---|---|
| 1. Extracted policy content | `src/sources/*.md` | Yes, but in the private `herk` repo, then copy in | `npm run extract && npm run validate` |
| 2. Authored data (risk callouts, flavor one-liners) | `src/_data/riskCallouts.js`, `scripts/extract.mjs` | Yes, directly | `npm run extract` if in extract.mjs; nothing extra if in riskCallouts.js |
| 3. Page-level template copy | `src/index.njk`, `src/jobs/*.njk`, `src/policies/*.njk`, `src/print/*.njk` | Yes, directly | `npm run build` (or just let `npm run dev` pick it up) |
| 4. Shared component copy | `src/_includes/macros.njk` | Yes, directly | `npm run build` |
| 5. Navigation & chrome | `src/_includes/nav.njk`, `footer.njk`, `base.njk`, `print.njk` | Yes, directly | `npm run build` |
| 6. Client-side JS strings | `src/assets/scripts.js` | Yes, directly | `npm run build` (passthrough-copied, no compile step) |
| 7. PDF-only text | `scripts/render-pdfs.mjs` | Yes, directly | `npm run pdfs` |
| 8. Front-matter titles | YAML front matter at the top of each `.njk` file | Yes, directly | `npm run build` |

Never hand-edit `data.json` or `src/assets/data.js` — both are build output, fully
regenerated by `npm run extract` every time it runs. `src/assets/data.js` is also
gitignored.

## 1. Extracted policy content

The 16 scenarios, violation questions, 64 policy paragraphs, and 4 dimension
definitions (operative question, Hi text, Lo text) are not written in this repo.
They live in two vendored markdown files, parsed by `scripts/extract.mjs`:

```
src/sources/workshop-1-policy-texts-v5.md          scenarios, violation arc, 16 policy texts
src/sources/operational-dimension-definitions.md    the 4 dimension definitions
```

**To change:** edit the source document in the private `herk` repo, copy the updated
file into `src/sources/` (overwrite), then run:

```bash
npm run extract    # re-parses src/sources/ -> data.json + src/assets/data.js
npm run validate   # confirms nothing broke (0 errors, 1 expected "Zip" warning)
```

`data.json` is committed, so its diff after `extract` is the reviewable record of what
text actually changed. Every downstream template reads this data through the global
`policy` variable (`src/_data/policy.js` re-exports `data.json`) or through `combo` /
`employee` / `flavor` pagination aliases — never as literal strings in a template.

## 2. Authored data (not extracted, but not inline in a template either)

Two small pieces of copy are hand-written but live in data files rather than in page
templates, because they're reused across several pages by id lookup:

- **`src/_data/riskCallouts.js`** — the two risk callouts (Puk/Yellow, Wow/Blue), each
  a `title` and `description` string, keyed by employee id then flavor id.
- **`scripts/extract.mjs`, the `FLAVORS` array** — the four one-line flavor
  `character` strings ("Most restrictive; maximum oversight", etc.). These are
  authored, not extracted from source, but they live in the extraction script (not
  `src/_data/`) because they're merged into `data.json` alongside the parsed
  dimension config for each flavor. **Changing them requires `npm run extract`**, even
  though nothing in `src/sources/` changed — a common trap.

`src/_data/combos.js` and `src/_data/policy.js` carry no authored text of their own;
they only reshape `data.json` for pagination and global access.

## 3. Page-level template copy

Headings, intro paragraphs, instructional text, and link labels written directly into
a page's `.njk` file, interpolated with data but not sourced from it. This is where
the example you quoted lives:

> "The same scenario, read against each of the four policy flavors in turn. Only the
> policy changes from column to column; the facts do not."

That sentence is a `<p class="lede">` in **`src/jobs/job-compare.njk`** — it's
UI-authored copy framing the comparison view, not policy content, so it isn't in
`data.json` and won't be touched by `npm run extract`.

Full inventory of where this kind of copy lives:

| File | What's authored there |
|---|---|
| `src/index.njk` | Overview headline, intro paragraph, "The four jobs" / "The four policy flavors" section headers, the closing link sentence |
| `src/about.njk` | The entire "About this site" help page: how the site is structured, how to navigate, how the two-flavor comparison works, printing/PDFs, accessibility. Reached only from the footer link, not from the nav. |
| `src/jobs/job-flavor.njk` | The "&larr; Compare all four flavors for..." back-link |
| `src/jobs/job-compare.njk` | The diff-view explainer lede (quoted above), the packet PDF link label |
| `src/policies/index.njk` | Matrix page intro paragraph, "The four operational dimensions" section header, its intro sentence, the compendium PDF link label |
| `src/policies/flavor.njk` | "Dimension definitions under {flavor}" and "The four jobs under {flavor}" headers, the Hi/Lo intro sentence |
| `src/print/single.njk` | No unique copy beyond shared macros; structurally identical to `job-flavor.njk` |
| `src/print/packet.njk` | The cover lede ("All four policy flavors, in order: Green, Red, Blue, Yellow.") |
| `src/print/compendium.njk` | The cover title and intro paragraph, "Contents" TOC header, "Operational dimension definitions" section header |

Section headings that name a *dimension* (Security/Accountability/Efficiency/
Innovation) are not typed out in these files — they call the `dimLabel()` macro
(category 4), so changing a dimension's display name means editing `macros.njk`, not
every page that shows it.

## 4. Shared component copy (macros)

**`src/_includes/macros.njk`** holds copy reused across many pages via macro calls
(`{{ verdict(...) }}`, `{{ riskCallout(...) }}`, etc.), so a change here changes every
page that uses that macro at once:

- `dimAbbrev` / `dimFull` — the lookup tables behind "Sec / Acct / Eff / Innov" chip
  abbreviations and full dimension names in headings. (Not the dimension *definitions*
  — those are category 1.)
- `verdict()` — the words "Compliant" / "Violation", and the templated sentence
  "Under this policy, {name}'s actions in the scenario ... violate the stated rules."
- `riskCallout()` — the "Risk: " prefix before each callout's authored title.
- `pdfLink()` — the default label "Download PDF" (most call sites override this with
  a more specific label passed as an argument; those overrides live at the call site,
  per the table in section 3).

## 5. Navigation & chrome

Structural, present on every page (or every print page):

| File | What's authored there |
|---|---|
| `src/_includes/nav.njk` | Tab labels: "Overview", "Jobs", "Policies"; the "Compare" vs. "Matrix" label logic for the fourth flavor-row tab |
| `src/_includes/footer.njk` | The footer attribution line ("Herkimer County AI Roles · illustrative training material...") and the "About this site" link to `/about/` |
| `src/_includes/base.njk` | "Skip to content" skip-link text; the `<title>` suffix "\| Herkimer County AI Roles" |
| `src/_includes/print.njk` | Same `<title>` suffix, for the print/PDF variant |

## 6. Client-side JS strings

**`src/assets/scripts.js`** builds some DOM text at runtime rather than rendering it
server-side, so it won't show up if you only grep `.njk` files:

- Diff control labels: "Compare", "with", "Show all four", "Choose a flavor"
- The visually-hidden "changed: " prefix marker inserted before a diff-highlighted
  paragraph

## 7. PDF-only text

The PDF footer (provenance line + page numbers) is injected directly by Playwright,
outside the Nunjucks template pipeline entirely, because Chromium's print engine
ignores CSS-generated footers:

**`scripts/render-pdfs.mjs`**, the `footerTemplate()` function — "Herkimer County AI
Roles · {version} · {generated date}" plus the page-number counters. Changing this
requires `npm run pdfs` (or `npm run all`) to regenerate all 21 PDFs; it has no effect
on the on-screen site.

## 8. Front-matter titles

Every `.njk` page sets a `title` used in `<title>{{ title }} | Herkimer County AI
Roles</title>` (via `base.njk` / `print.njk`). Two kinds:

- **Static**, plain YAML: `src/index.njk`, `src/policies/index.njk`
  (`title: Overview`, `title: Policy Matrix`)
- **Computed**, a Nunjucks template string evaluated per pagination item via
  `eleventyComputed`: `src/jobs/job-flavor.njk`, `src/jobs/job-compare.njk`,
  `src/policies/flavor.njk`, and all three `src/print/*.njk` files. These interpolate
  `combo.employee.name`, `flavor.name`, etc. — edit the template string in the
  front matter, not a separate title elsewhere.

## What is *not* site content

Two things read like copy but never reach a browser or a PDF:

- **`docs/*.md`** — project documentation (this file included). Not part of the
  Eleventy input tree; `eleventy.config.js` explicitly ignores `src/sources/**` for
  the same reason (see that file's comment), and `docs/` was never inside `src/` to
  begin with.
- **`console.log` / `console.error` strings in `scripts/*.mjs`** — build-time
  diagnostics (`extract.mjs`, `validate.mjs`, `check-portable.mjs`,
  `render-pdfs.mjs`), read by whoever runs the command, never rendered on the site.

## Finding a specific string fast

```bash
grep -rn "exact phrase" src/ scripts/
```

covers every category above except category 6 in its DOM-templated form (search
`scripts.js` directly for shorter fragments, since it's built up via
`.textContent = ...` rather than written as literal HTML) and category 1's raw source
text (search `src/sources/*.md` directly; the extracted copy in `data.json` is a
straight substring of it, so a match in one is a match in the other).
